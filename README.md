## 1. About the Assignment

This assignment focuses on designing and evaluating a reliable network infrastructure for a smart manufacturing plant.

The plant contains industrial robot controllers, vibration sensors, CCTV cameras, office users and autonomous guided vehicles (AGVs). These devices generate different types of network traffic with different bandwidth, reliability and latency requirements.

The main objective is to ensure that data reaches its destination correctly and on time while maintaining network performance, scalability and reliability.

The assignment covers the following concepts:

- Network traffic calculation and capacity planning
- Collision domains and broadcast domains
- OSI model and network standards
- Ethernet framing and encapsulation
- Transmission media and channel capacity
- Wi-Fi 6 and private 5G
- Ethernet diagnostics and troubleshooting
- Error detection and error correction
- Sliding window protocols and ARQ
- Network delay analysis
- Network design evaluation and scalability
- Private 5G integration for AGVs

## 3. Task Overview

### Task 1 – Size the Traffic Before Choosing Anything

Calculated the traffic generated by robot controllers, vibration sensors, CCTV cameras and office users.

Key findings:
- Traffic generated by one production line: **158.24 Mbps**
- Traffic generated by eight production lines: **1,265.92 Mbps**
- Motion-triggered CCTV reduces the estimated eight-line traffic to **536.32 Mbps**.
- A single 1 Gbps uplink is insufficient for the original continuous-streaming traffic estimate.

### Task 2 – Count the Collision and Broadcast Domains

Analysed the contractor's network topology containing hubs, switches, PCs, IP phones and a router.

Key findings:
- Original topology: 17 collision domains.
- Original topology: 2 broadcast domains, assuming one subnet per router interface.
- Replacing hubs with switches increases the collision-domain count to 41 under the stated topology assumptions.
- Identified the OSI layers and relevant networking standards.

### Task 3 – Read a Captured Frame Layer by Layer

Studied Ethernet II, IPv4, TCP and application-layer information in a robot command frame.

The task demonstrates:
- Encapsulation and decapsulation.
- Ethernet, IP and TCP header information.
- Protocol identification and port numbers.
- Protocol overhead and industrial Ethernet alternatives.

### Task 4 – Choose a Transmission Medium

Evaluated suitable transmission media for different plant connections.

The task covers:
- Cat6 and shielded Cat6A Ethernet.
- Multimode and single-mode fibre.
- Transmission distance limitations.
- Nyquist theorem and Shannon capacity.
- Effects of electrical noise near welding equipment.

### Task 5 – Wi-Fi 6 or 5G for Moving Equipment?

Compared Wi-Fi 6 and private 5G for autonomous guided vehicles.

Key findings:
- Wi-Fi handover time: approximately 150 ms.
- Private 5G handover time: approximately 20 ms.
- Required robot command deadline: 10 ms.
- Private 5G provides lower handover interruption than Wi-Fi in the given scenario.
- Evaluated eMBB, URLLC and mMTC service types.

### Task 6 – Interpret an Ethernet Port Report

Analysed Ethernet interface diagnostics and identified possible causes of poor network performance.

The task covers:
- Late collisions and CRC errors.
- Duplex mismatch.
- Ethernet speed and duplex configuration.
- MAC address identification.
- Jumbo frames.
- Industrial Ethernet ring and star topologies.

### Task 7 – Will the Receiver Notice the Error?

Implemented CRC-based error detection using Python.

The task covers:
- CRC generation and verification.
- Binary modulo-2 division.
- Error detection using a received frame.
- Burst-error detection.
- Two-dimensional parity and Internet checksum comparisons.

### Task 8 – Can the Receiver Correct the Error?

Implemented Hamming-code error correction using Python.

The task covers:
- Hamming parity-bit calculation.
- Syndrome generation.
- Single-bit error detection and correction.
- Minimum Hamming distance.
- Forward Error Correction (FEC) and Automatic Repeat Request (ARQ) comparison.

### Task 9 – Keep the Link Busy Without Losing Frames

Analysed sliding-window protocols and flow control for long-distance communication.

Key findings:
- Stop-and-Wait utilisation on the 400 km link: approximately 0.3%.
- Required window size for theoretical full utilisation: 335 frames.
- Go-Back-N and Selective Repeat comparisons.
- Bit stuffing and HDLC/PPP framing.
- Satellite-link utilisation calculations.

### Task 10 – Find Where the Delay Comes From

Analysed traceroute and ping results to understand network delay.

The task covers:
- Propagation delay over 400 km of fibre.
- Round-trip-time analysis.
- Variable router response times.
- Non-responsive traceroute hops.
- SNMP and NetFlow monitoring.

The repository contains traceroute and ping evidence. The Wireshark-style screenshot is an illustrative sample, not an actual packet capture. A genuine Wireshark capture remains to be added.

### Task 11 – Defend the Network Design

Combined the findings from Tasks 1–10 to recommend a suitable network architecture.

The recommended design uses:
- Shielded Ethernet for industrial connections.
- Fibre for high-capacity backbone links.
- Wi-Fi 6 for office users.
- Private 5G for mobile equipment.
- QoS and traffic prioritisation.
- Suitable error-control and flow-control methods.

The design was also evaluated for expansion to five plants.

### Task 12 – Re-evaluate and Adapt the Design

Evaluated the original network after introducing private 5G and 50 AGVs.

Key findings:
- Estimated additional AGV traffic: **40 Mbps**.
- Revised estimated traffic per plant: **1.30592 Gbps**.
- Wi-Fi handover interruption: **150 ms**.
- Private 5G handover interruption: **20 ms**.
- Required command deadline: **10 ms**.

The final decision is to **modify the original hybrid network design** by introducing private 5G for AGVs while retaining wired Ethernet and fibre for critical fixed connections.

*AGV traffic is estimated using the Task 1 robot-controller pattern of 200-byte commands every 2 ms. This is an explicit assumption because the assignment does not specify a separate AGV command rate.*

## 7. Final Network Recommendation

Based on the analysis of all twelve tasks, a hybrid network architecture is recommended for the smart manufacturing plant.

| Requirement | Recommended Solution |
|---|---|
| Fixed robot controllers | Shielded Cat6A Ethernet |
| Mobile AGVs | Private 5G with URLLC-oriented configuration |
| Office users | Wi-Fi 6 |
| CCTV | Wired Ethernet and fibre with local recording |
| Low-rate sensors | Suitable Zigbee or LoRaWAN connections |
| Plant backbone | Redundant 10 Gbps or higher fibre |
| Error detection | CRC |
| Error correction | Suitable FEC where supported |
| Traffic management | QoS and priority queuing |
| Long-distance communication | Single-mode fibre / leased fibre |

The design retains the reliability and capacity of wired connections while using wireless technologies where mobility is necessary.

Private 5G improves connectivity for moving AGVs, but its stated 20 ms handover time still exceeds the 10 ms command deadline. Therefore, additional latency optimisation, redundancy and local fail-safe control are necessary.
